2. Introduction & Problem Statement

In modern computer environments, user operations cross between web browsers (Google Chrome, Microsoft Edge) and desktop software (compilers, word processors, local downloads). When security anomalies, file leaks, or workstation incidents occur, reconstructive forensic triage requires determining exactly what actions took place in strict chronological sequence.

Problem Statement: Digital activity artifacts are dispersed across proprietary, incompatible file formats (SQLite databases for browser history, binary .lnk structures for recently accessed files, file system timestamps). Existing commercial forensics suites (such as EnCase or FTK Imager) are proprietary, heavy (~1 GB), and steep in complexity for rapid incident auditing.

Proposed Solution: TraceLens is an open-source, lightweight desktop forensics tool developed in Python 3. It parses Chromium SQLite databases, Windows Recent artifacts, and user downloads, normalizes disparate epochs into human-readable local time, and provides an interactive graphical timeline with real-time filtering, visual analytics, and exportable forensic audit reports.

3. Dataset Used

TraceLens utilizes real workstation forensic repositories alongside a standardized laboratory case study:

  • Live Chromium SQLite History: Extracted from %LOCALAPPDATA%\Google\Chrome\User Data\Default\History and Microsoft Edge equivalent. Contains visit URLs, page titles, visit counts, and download records.
  • Windows OS Recent Shortcuts: Extracted from %APPDATA%\Microsoft\Windows\Recent. Binary .lnk shortcuts indicating file/application access times.
  • Live OS Sockets & DNS Resolver Cache: Active TCP/UDP endpoints mapped to browser PIDs and system DNS cache for Incognito/InPrivate forensic detection.
  • Simulated Forensic Incident Scenario: 20 chronological forensic events (searches, proxy lookups, bypass downloads, app launches, document drafts) enabling instant demonstration without scanning personal workstation data.
4. Algorithms & Flowcharts of Functions

Algorithm 1: Safe Shadow Database Cloning & WebKit Epoch Conversion

Step 1: Check if history path exists in %LOCALAPPDATA% Step 2: Create a unique temporary file path using tempfile.NamedTemporaryFile() Step 3: Copy locked database to temporary file using shutil.copy2() Step 4: Establish sqlite3 connection to the temporary clone Step 5: Query 'urls' table for URL, Title, Visit Count, and Last Visit Time Step 6: For each record, calculate: Datetime = Epoch(1601-01-01 UTC) + timedelta(microseconds = last_visit_time) Step 7: Parse URL parameters for queries (?q=, search_query=) using urllib.parse Step 8: Close sqlite3 connection and delete temporary clone from disk

6. Conclusion & Future Scope

The TraceLens project successfully fulfills all prescribed mini-project objectives. Built entirely with Python 3 and standard desktop libraries, it bridges the gap between complex enterprise forensic suites and introductory incident response needs. The application reliably bypasses database locks, standardizes diverse epoch formats, and delivers clear chronological timeline insights with embedded visual analytics.

Future Scope: Enhancements include adding support for Mozilla Firefox (places.sqlite), session cookie cache inspection, and compiling the codebase into a single executable binary using PyInstaller.
