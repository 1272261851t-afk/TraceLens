1 Dataset Description

The TraceLens system consumes digital forensic artifacts gathered from heterogeneous sources on the host workstation. Rather than requiring external synthetic datasets, TraceLens dynamically interfaces with local system data repositories and includes a standardized benchmark case study.

2 Data Preprocessing & Analysis Tasks Performed

Because digital artifacts originate in disparate proprietary schemas, several multi-stage data preprocessing pipelines were implemented:

A. Active Database Lock Handling (Shadow Cloning):
Active browsers hold exclusive write locks on their SQLite database files, causing fatal sqlite3.OperationalError when queried directly. TraceLens safely clones the database to %TEMP% using shutil.copy2, executes queries against the clone, and immediately unlinks the temporary file.

B. Epoch Conversion & Timestamp Normalization:
Chromium records time as microseconds elapsed since January 1, 1601 UTC, whereas Windows file systems use standard Unix epochs (seconds since 1970). We mathematically normalize all timestamps into uniform Python datetime objects and formatted ISO strings (YYYY-MM-DD HH:MM:SS):

def chrome_time_to_datetime(chrome_timestamp): # WebKit epoch start: 1601-01-01 UTC return datetime(1601, 1, 1) + timedelta(microseconds=chrome_timestamp)

C. Search Query Extraction:
Raw URLs are deconstructed using urllib.parse.urlparse and parse_qs to extract keywords from query parameters (e.g. ?q= for Google/Bing, search_query= for YouTube) using unquote_plus, isolating search intentions from navigational visits.

D. Heuristic File Type Classification:
Extensions of accessed files are categorized into functional groups (Documents, Source Code, Media, Executables, and Archives) to facilitate domain-level forensic analysis.

E. Multi-Stream Chronological Merging:
Disparate streams are merged into a single list of standardized dictionaries and sorted using high-performance in-memory sorting: artifacts.sort(key=lambda x: x["dt"], reverse=True).
